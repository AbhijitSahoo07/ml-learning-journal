# Knuth-Morris-Pratt (KMP) Algorithm

## Overview

The Knuth-Morris-Pratt (KMP) algorithm is a highly efficient string-searching algorithm. Its primary purpose is to find occurrences of a "pattern" string within a larger "text" string. Unlike simpler, "naive" string-searching algorithms that might re-examine characters in the text multiple times after a mismatch, KMP is designed to avoid redundant comparisons. It achieves this by intelligently pre-processing the pattern to understand its internal structure, specifically identifying how much the pattern can be shifted forward after a mismatch without missing any potential matches. This pre-processing step creates a "prefix function" or "LPS array" (Longest Proper Prefix which is also a Suffix), which guides the search process, allowing KMP to perform the search in linear time relative to the combined lengths of the text and pattern.

## What Problem It Solves

The KMP algorithm addresses the fundamental problem of **efficient substring search**. Imagine you have a very long document (the "text") and you want to find all instances of a specific word or phrase (the "pattern").

Let's consider the challenges with a naive approach:

1.  **Redundant Comparisons**: A naive algorithm would start comparing the pattern with the text from the beginning. If a mismatch occurs, say at the 5th character, it would then shift the pattern by just one position and start comparing again from the 2nd character of the text. This means characters in the text that were already matched might be re-compared multiple times.
    *   **Example**: Text = "AAAAAB", Pattern = "AAB"
        *   Compare "AAB" with "AAA..." -> Mismatch at 3rd char (B vs A).
        *   Naive shifts pattern by 1. Compare "AAB" with "AA..." -> Mismatch at 3rd char (B vs A).
        *   ... and so on. This is inefficient.

2.  **Worst-Case Performance**: For certain patterns and texts (like the "AAAAAB" example), a naive algorithm can have a worst-case time complexity of $O(M \times N)$, where $N$ is the length of the text and $M$ is the length of the pattern. For very long texts and patterns, this can be prohibitively slow.

The KMP algorithm solves these problems by:

*   **Avoiding Backtracking in Text**: When a mismatch occurs, KMP doesn't backtrack the text pointer. It only shifts the pattern forward based on the information gathered during pattern pre-processing.
*   **Leveraging Partial Matches**: If a partial match has already occurred before a mismatch, KMP uses this information. It knows how much of the partially matched pattern can serve as a prefix for a potential new match, thus allowing for larger, more intelligent shifts.

**Why is it needed in machine learning?**

While KMP isn't a machine learning model itself, string searching is a foundational operation in many areas that support ML workflows, especially in Natural Language Processing (NLP) and bioinformatics:

*   **Text Preprocessing in NLP**: Before training models, text often needs cleaning, tokenization, or feature extraction. KMP can be used for:
    *   **Finding specific keywords or phrases**: Identifying sentiment indicators, named entities, or domain-specific terms.
    *   **Plagiarism detection**: Comparing documents for identical or highly similar sequences of words.
    *   **Data anonymization**: Finding and replacing sensitive patterns (e.g., social security numbers, email addresses) in text data.
*   **Bioinformatics**: DNA and protein sequences are essentially long strings of characters. KMP is crucial for:
    *   **Genome sequencing**: Finding specific gene sequences or regulatory elements within a larger genome.
    *   **Sequence alignment**: Identifying common patterns or motifs between different biological sequences.
*   **Log Analysis and Anomaly Detection**: In system logs, specific error patterns or malicious activity signatures can be identified using efficient string matching.
*   **Data Compression**: Identifying repeating patterns in data streams to encode them more efficiently.

In these contexts, the efficiency of KMP can significantly speed up data preparation and analysis, which are critical steps before or during machine learning model training and inference.

## How It Works

The KMP algorithm works in two main phases:

1.  **Pre-processing the Pattern (Building the LPS Array)**: This phase analyzes the pattern itself to build a "Longest Proper Prefix which is also a Suffix" (LPS) array. This array tells us, for any prefix of the pattern, what is the length of the longest proper prefix of that prefix that is also a suffix of that prefix. This sounds complicated, but it's essentially figuring out how much of the pattern has already been "matched" if a mismatch occurs.
2.  **Searching for the Pattern in the Text**: This phase uses the pre-computed LPS array to efficiently search for the pattern in the text.

Let's break down each phase:

### Phase 1: Building the LPS Array (also known as the "prefix function" or "failure function")

The LPS array, let's call it `lps[]`, for a pattern `P` of length `M`, stores `lps[i]` as the length of the longest proper prefix of `P[0...i]` that is also a suffix of `P[0...i]`. A "proper prefix" means it's not the entire string itself.

**Example**: Pattern `P = "ABABCABAB"`

*   `lps[0]` for "A": Longest proper prefix of "A" that is also a suffix of "A" is an empty string, length 0. So, `lps[0] = 0`.
*   `lps[1]` for "AB": Proper prefixes: "A". Proper suffixes: "B". No match. `lps[1] = 0`.
*   `lps[2]` for "ABA": Proper prefixes: "A", "AB". Proper suffixes: "A", "BA". Longest match is "A", length 1. `lps[2] = 1`.
*   `lps[3]` for "ABAB": Proper prefixes: "A", "AB", "ABA". Proper suffixes: "B", "AB", "BAB". Longest match is "AB", length 2. `lps[3] = 2`.
*   `lps[4]` for "ABABC": Proper prefixes: "A", "AB", "ABA", "ABAB". Proper suffixes: "C", "BC", "ABC", "BABC". No match. `lps[4] = 0`.
*   `lps[5]` for "ABabca": Proper prefixes: "A", "AB", "ABA", "ABAB", "ABABC". Proper suffixes: "A", "CA", "BCA", "ABCA", "BABCA". Longest match is "A", length 1. `lps[5] = 1`.
*   `lps[6]` for "ABabcab": Longest match is "AB", length 2. `lps[6] = 2`.
*   `lps[7]` for "ABabcaba": Longest match is "ABA", length 3. `lps[7] = 3`.
*   `lps[8]` for "ABabcabab": Longest match is "ABAB", length 4. `lps[8] = 4`.

So, for `P = "ABABCABAB"`, `lps = [0, 0, 1, 2, 0, 1, 2, 3, 4]`.

**How to build it algorithmically:**

1.  Initialize `lps[0] = 0`.
2.  Use two pointers: `length` (for the length of the previous longest prefix suffix) and `i` (to iterate through the pattern).
3.  If `P[i]` matches `P[length]`, increment both `length` and `i`, and set `lps[i] = length`.
4.  If `P[i]` does not match `P[length]`:
    *   If `length` is not 0, set `length = lps[length - 1]`. This means we try a shorter prefix-suffix match.
    *   If `length` is 0, set `lps[i] = 0` and increment `i`.

This process takes $O(M)$ time.

### Phase 2: Searching for the Pattern in the Text

Now, with the `lps` array, we can search the text `T` (length `N`) for the pattern `P` (length `M`).

1.  Use two pointers: `i` for the text (`T`) and `j` for the pattern (`P`).
2.  Compare `T[i]` and `P[j]`:
    *   **If they match (`T[i] == P[j]`)**: Increment both `i` and `j`. If `j` reaches `M` (meaning the entire pattern has been matched), we've found an occurrence! Record the starting index (`i - M`) and then, to find further occurrences, set `j = lps[j - 1]` (this shifts the pattern to look for overlapping matches).
    *   **If they don't match (`T[i] != P[j]`)**:
        *   If `j` is not 0, it means we had a partial match. We don't backtrack `i`. Instead, we shift the pattern by setting `j = lps[j - 1]`. This effectively aligns the next possible prefix-suffix match of the pattern with the current text position.
        *   If `j` is 0, it means the first character of the pattern didn't match, so we just increment `i` to move to the next character in the text.

This process takes $O(N)$ time.

**Total Time Complexity**: $O(M) + O(N) = O(N+M)$. This is highly efficient!

## Mathematical Intuition

The core mathematical intuition behind KMP lies in the efficient utilization of information about the pattern's structure to avoid redundant comparisons. This information is encapsulated in the **LPS (Longest Proper Prefix which is also a Suffix) array**.

Let $P$ be the pattern string of length $M$, and $T$ be the text string of length $N$.

### 1. The LPS Array (Prefix Function)

For a pattern $P$, the LPS array, denoted as $\pi$ (or `lps` in code), is an array of length $M$. Each entry $\pi[q]$ for $q \in \{0, 1, \dots, M-1\}$ stores the length of the longest proper prefix of the substring $P[0 \dots q]$ that is also a suffix of $P[0 \dots q]$.

*   **Proper Prefix**: A prefix of a string that is not the string itself. For $S = \text{"ABC"}$, proper prefixes are $\text{"A"}$, $\text{"AB"}$.
*   **Proper Suffix**: A suffix of a string that is not the string itself. For $S = \text{"ABC"}$, proper suffixes are $\text{"C"}$, $\text{"BC"}$.

**Example**: $P = \text{"ABABA"}$
*   $\pi[0]$ for $\text{"A"}$: No proper prefix/suffix. Length 0. $\pi[0] = 0$.
*   $\pi[1]$ for $\text{"AB"}$: Proper prefixes: $\text{"A"}$. Proper suffixes: $\text{"B"}$. No match. Length 0. $\pi[1] = 0$.
*   $\pi[2]$ for $\text{"ABA"}$: Proper prefixes: $\text{"A", "AB"}$. Proper suffixes: $\text{"A", "BA"}$. Longest match: $\text{"A"}$. Length 1. $\pi[2] = 1$.
*   $\pi[3]$ for $\text{"ABAB"}$: Proper prefixes: $\text{"A", "AB", "ABA"}$. Proper suffixes: $\text{"B", "AB", "BAB"}$. Longest match: $\text{"AB"}$. Length 2. $\pi[3] = 2$.
*   $\pi[4]$ for $\text{"ABABA"}$: Proper prefixes: $\text{"A", "AB", "ABA", "ABAB"}$. Proper suffixes: $\text{"A", "BA", "ABA", "BABA"}$. Longest match: $\text{"ABA"}$. Length 3. $\pi[4] = 3$.

So, for $P = \text{"ABABA"}$, $\pi = [0, 0, 1, 2, 3]$.

### 2. Building the LPS Array (Algorithm for $\pi$)

The $\pi$ array can be computed in $O(M)$ time using a dynamic programming-like approach. We maintain a `length` variable, which represents the length of the longest proper prefix suffix found so far for the current prefix.

Let `length` be the length of the previous longest prefix suffix (initially 0).
Let `i` be the current index in the pattern (starting from 1).

The recurrence relation for computing $\pi[i]$ is:

If $P[i] = P[\text{length}]$:
$$ \text{length} = \text{length} + 1 $$
$$ \pi[i] = \text{length} $$

If $P[i] \neq P[\text{length}]$:
*   If $\text{length} \neq 0$:
    $$ \text{length} = \pi[\text{length} - 1] $$
    (We try a shorter prefix-suffix match by looking up the LPS value for the prefix of length `length-1`).
*   If $\text{length} = 0$:
    $$ \pi[i] = 0 $$
    (No prefix-suffix match found, reset `length` to 0).

This process continues until `i` reaches $M-1$.

### 3. Searching with the LPS Array

When searching for $P$ in $T$, we use two pointers:
*   $i$: index for the text $T$.
*   $j$: index for the pattern $P$.

The core idea is that if a mismatch occurs at $T[i]$ and $P[j]$ (i.e., $T[i] \neq P[j]$), we know that the substring $P[0 \dots j-1]$ has successfully matched $T[i-j \dots i-1]$.
Instead of shifting the pattern by just one position and re-comparing, we can make a more informed shift. We know that $P[0 \dots \pi[j-1]]$ is the longest proper prefix of $P[0 \dots j-1]$ that is also a suffix of $P[0 \dots j-1]$.
This means that the prefix $P[0 \dots \pi[j-1]]$ *could* potentially align with the suffix $T[i - \pi[j-1] \dots i-1]$ (which is part of the previously matched segment in $T$).

So, upon a mismatch at $P[j]$:
*   If $j \neq 0$: We set $j = \pi[j-1]$. This effectively shifts the pattern such that the prefix of length $\pi[j-1]$ aligns with the previously matched suffix in the text. The text pointer $i$ does *not* backtrack.
*   If $j = 0$: This means the first character of the pattern didn't match. We simply increment $i$ (move to the next character in text) and keep $j=0$.

When a full match is found (i.e., $j = M$):
*   We record the match at $T[i-M]$.
*   To find overlapping matches, we then set $j = \pi[j-1]$ (which is $\pi[M-1]$). This allows the algorithm to continue searching for the pattern starting from the next possible overlapping match.

This intelligent shifting ensures that we never re-examine characters in the text that have already been matched, leading to the optimal $O(N+M)$ time complexity. The mathematical elegance lies in how the $\pi$ array pre-computes all necessary shift information, making the search phase a single, efficient pass.

## Advantages

*   **Optimal Time Complexity**: The KMP algorithm has a time complexity of $O(N+M)$, where $N$ is the length of the text and $M$ is the length of the pattern. This is linear and considered optimal for string searching, as every character in both the text and pattern must be examined at least once.
*   **No Backtracking in Text**: Unlike naive algorithms, KMP never moves the text pointer (`i`) backward. This is a significant efficiency gain, especially for very long texts.
*   **Efficient for Repetitive Patterns**: KMP performs exceptionally well when the pattern contains many repeating characters or sub-patterns (e.g., "AAAAAB"). The LPS array effectively captures this repetitiveness, allowing for larger shifts.
*   **Guaranteed Performance**: The $O(N+M)$ complexity is a worst-case guarantee, meaning its performance doesn't degrade significantly with specific input types.
*   **Space-Efficient (Relatively)**: It only requires $O(M)$ extra space for the LPS array, which is proportional to the pattern length, not the text length.

## Disadvantages

*   **Complexity of Understanding and Implementation**: KMP is more complex to understand and implement correctly compared to the naive string-searching algorithm. The logic behind the LPS array and its construction can be tricky for beginners.
*   **Pre-processing Overhead**: While the pre-processing phase is efficient ($O(M)$), it still adds an initial overhead. For very short texts or patterns, or when searching for a pattern only once in a very small text, the overhead might slightly outweigh the benefits of the optimized search.
*   **Not Always the Fastest in Practice for Random Text**: For typical random text and patterns, other algorithms like Boyer-Moore (which often has a sub-linear average case) can sometimes be faster in practice, although Boyer-Moore's worst-case complexity is higher. KMP's strength is its guaranteed linear time.
*   **Limited to Exact String Matching**: KMP is designed for exact string matching. It cannot directly handle approximate string matching (e.g., finding patterns with a few errors or variations) without modifications or integration with other techniques.

## Real World Applications

1.  **Text Editors and IDEs (Find/Replace Functionality)**:
    *   When you use the "Find" or "Find and Replace" feature in a text editor, word processor, or Integrated Development Environment (IDE), an efficient string-searching algorithm like KMP (or similar optimized algorithms) is often working behind the scenes. It quickly locates all occurrences of your search query within the document, even very large ones, ensuring a smooth user experience.

2.  **Bioinformatics (DNA and Protein Sequence Analysis)**:
    *   In genomics and proteomics, biological sequences (DNA, RNA, proteins) are represented as long strings of characters (e.g., A, T, C, G for DNA). KMP is used to:
        *   **Locate specific genes or motifs**: Find known gene sequences or regulatory elements within a vast genome.
        *   **Identify homologous sequences**: Search for similar patterns across different species' genomes to understand evolutionary relationships.
        *   **Primer design**: Find unique sequences for PCR primers.
    *   The efficiency of KMP is critical here due to the immense size of genomic data.

3.  **Network Intrusion Detection Systems (NIDS) and Firewalls**:
    *   NIDS and firewalls inspect network packet payloads for known malicious patterns or signatures (e.g., specific byte sequences indicating a virus, malware, or attack attempt). KMP can be employed to quickly scan incoming data streams for these predefined patterns. Its linear time complexity is crucial for real-time performance, as network traffic can be very high-volume.

4.  **Plagiarism Detection Software**:
    *   Plagiarism detection tools compare submitted documents against a vast database of existing texts (web pages, academic papers, etc.). KMP can be used as a component to efficiently find exact or near-exact matches of phrases, sentences, or longer blocks of text between documents, helping to identify instances of copied content.

5.  **Data Compression and Archiving**:
    *   Algorithms like LZ77 (used in ZIP, GZIP) rely on finding repeating patterns within a data stream to replace them with shorter references. While LZ77 itself uses a sliding window and hash tables for efficiency, the underlying principle of identifying repeating substrings is a core string-matching problem where KMP's logic could be adapted or inspire similar pattern-finding mechanisms. By efficiently identifying and encoding these repetitions, KMP-like approaches contribute to reducing file sizes.

## Python Example

This Python example demonstrates the Knuth-Morris-Pratt (KMP) algorithm. It includes two main functions:
1.  `compute_lps_array`: To pre-process the pattern and build the LPS (Longest Proper Prefix which is also a Suffix) array.
2.  `kmp_search`: To use the LPS array to find all occurrences of the pattern in the text.

```python
import numpy as np # Although not strictly necessary for KMP, included as per request for popular libraries.
                   # For string operations, standard Python strings are efficient.

def compute_lps_array(pattern):
    """
    Computes the Longest Proper Prefix which is also a Suffix (LPS) array for the given pattern.
    The LPS array helps to know the longest prefix of the pattern that is also a suffix
    of the pattern's prefix up to the current index. This information is used to avoid
    re-matching characters when a mismatch occurs during the search.

    Args:
        pattern (str): The pattern string for which to compute the LPS array.

    Returns:
        list: The LPS array.
    """
    M = len(pattern)
    lps = [0] * M  # Initialize LPS array with zeros
    length = 0     # Length of the previous longest prefix suffix
    i = 1          # Start from the second character of the pattern

    # Loop to compute lps[i] for i = 1 to M-1
    while i < M:
        if pattern[i] == pattern[length]:
            length += 1
            lps[i] = length
            i += 1
        else:
            # This is tricky. If there's a mismatch, we don't reset length to 0 immediately.
            # We look at the LPS value of the previous character (length-1) to find
            # a shorter prefix that could still be a suffix.
            if length != 0:
                length = lps[length - 1]
            else:
                # If length is 0, it means no prefix-suffix match found for current i,
                # so lps[i] remains 0, and we move to the next character in pattern.
                lps[i] = 0
                i += 1
    return lps

def kmp_search(text, pattern):
    """
    Searches for all occurrences of the pattern in the text using the KMP algorithm.

    Args:
        text (str): The main text string to search within.
        pattern (str): The pattern string to search for.

    Returns:
        list: A list of starting indices where the pattern is found in the text.
    """
    N = len(text)
    M = len(pattern)

    if M == 0:
        return [i for i in range(N + 1)] # Empty pattern matches everywhere
    if N == 0:
        return [] # No text to search in

    lps = compute_lps_array(pattern) # Pre-process the pattern

    # Pointers for text and pattern
    i = 0  # index for text[]
    j = 0  # index for pattern[]

    found_indices = []

    while i < N:
        if pattern[j] == text[i]:
            i += 1
            j += 1

        if j == M:
            # Pattern found at index (i - j)
            found_indices.append(i - j)
            # To find overlapping occurrences, we don't stop.
            # We use the LPS array to shift the pattern for the next possible match.
            j = lps[j - 1]
        elif i < N and pattern[j] != text[i]:
            # Mismatch after j matches
            if j != 0:
                # Do not match lps[0...lps[j-1]] characters,
                # they will match anyway
                j = lps[j - 1]
            else:
                # If j is 0, it means the first character of the pattern didn't match.
                # Just move to the next character in the text.
                i += 1
    return found_indices

# --- Demonstration ---
if __name__ == "__main__":
    # Example 1: Basic search
    text1 = "ABABDABACDABABCABAB"
    pattern1 = "ABABCABAB"
    print(f"Text: '{text1}'")
    print(f"Pattern: '{pattern1}'")

    lps_array1 = compute_lps_array(pattern1)
    print(f"LPS array for pattern1: {lps_array1}")
```

**Explanation of the Code:**

1.  **`compute_lps_array(pattern)`**:
    *   Initializes an `lps` array of the same length as the `pattern` with all zeros.
    *   `length` tracks the length of the longest proper prefix that is also a suffix for the prefix `pattern[0...i-1]`.
    *   `i` iterates through the `pattern` from the second character (`i=1`).
    *   If `pattern[i]` matches `pattern[length]`, it means we've extended the current prefix-suffix match. So, `length` is incremented, and `lps[i]` is set to this new `length`.
    *   If there's a mismatch (`pattern[i] != pattern[length]`):
        *   If `length` is not zero, it means we had a partial match. We don't reset `length` to zero. Instead, we try to find a shorter prefix that could still be a suffix by setting `length = lps[length - 1]`. This is the core KMP optimization.
        *   If `length` is already zero, it means no prefix-suffix match was found for `pattern[0...i]`, so `lps[i]` remains 0, and we just move to the next character `i`.

2.  **`kmp_search(text, pattern)`**:
    *   Handles edge cases for empty `pattern` or `text`.
    *   Calls `compute_lps_array` to get the `lps` array.
    *   `i` is the pointer for the `text`, `j` is the pointer for the `pattern`.
    *   It iterates through the `text` (`while i < N`):
        *   If `pattern[j]` matches `text[i]`, both pointers are incremented.
        *   If `j` reaches `M` (the length of the pattern), it means a full match is found. The starting index `(i - j)` is recorded. To find overlapping matches, `j` is then updated to `lps[j - 1]`, effectively shifting the pattern.
        *   If there's a mismatch (`pattern[j] != text[i]`):
            *   If `j` is not zero, it means a partial match occurred. We use `lps[j - 1]` to shift the pattern, effectively setting `j` to the length of the longest proper prefix of `pattern[0...j-1]` that is also its suffix. The `text` pointer `i` does *not* backtrack.
            *   If `j` is zero, it means the first character of the pattern didn't match. We simply increment `i` to move to the next character in the `text`.

The `if __name__ == "__main__":` block provides several test cases to demonstrate the algorithm's behavior in different scenarios.

## Interview Questions

Here are some common interview questions about the KMP algorithm, along with detailed answers:

1.  **What is the Knuth-Morris-Pratt (KMP) algorithm, and what problem does it solve?**
    *   **Answer**: KMP is an efficient string-searching algorithm used to find occurrences of a "pattern" string within a larger "text" string. It solves the problem of inefficient string searching by avoiding redundant comparisons (backtracking) in the text, achieving a linear time complexity of $O(N+M)$ where $N$ is text length and $M$ is pattern length.

2.  **How does KMP improve upon the naive string-searching algorithm?**
    *   **Answer**: The naive algorithm can have a worst-case time complexity of $O(N \times M)$ because it might repeatedly re-examine characters in the text after a mismatch. KMP improves this by:
        *   **Pre-processing the pattern**: It builds an LPS (Longest Proper Prefix which is also a Suffix) array for the pattern.
        *   **Intelligent shifting**: When a mismatch occurs, KMP uses the LPS array to determine the largest possible shift of the pattern without missing any potential matches. Crucially, the text pointer never moves backward.

3.  **Explain the purpose of the "LPS array" (or prefix function/failure function) in KMP.**
    *   **Answer**: The LPS array, for a pattern `P` of length `M`, stores at each index `i` the length of the longest proper prefix of `P[0...i]` that is also a suffix of `P[0...i]`. Its purpose is to guide the pattern shifting. When a mismatch occurs at `P[j]`, the LPS array tells us how many characters from the beginning of the pattern can be aligned with the end of the partially matched segment in the text, allowing for an efficient shift without re-scanning the text.

4.  **Walk through an example of how the LPS array is constructed for the pattern "ABABA".**
    *   **Answer**:
        *   `P = "ABABA"`, `M = 5`. `lps` array initialized to `[0, 0, 0, 0, 0]`.
        *   `lps[0]` is always 0.
        *   `i=1`, `length=0`: `P[1]` ('B') != `P[0]` ('A'). `length` is 0, so `lps[1]=0`, `i` becomes 2.
        *   `i=2`, `length=0`: `P[2]` ('A') == `P[0]` ('A'). `length` becomes 1. `lps[2]=1`. `i` becomes 3.
        *   `i=3`, `length=1`: `P[3]` ('B') == `P[1]` ('B'). `length` becomes 2. `lps[3]=2`. `i` becomes 4.
        *   `i=4`, `length=2`: `P[4]` ('A') == `P[2]` ('A'). `length` becomes 3. `lps[4]=3`. `i` becomes 5.
        *   Loop ends. Final `lps` array: `[0, 0, 1, 2, 3]`.

5.  **What is the time and space complexity of the KMP algorithm?**
    *   **Answer**:
        *   **Time Complexity**: $O(N+M)$, where $N$ is the length of the text and $M$ is the length of the pattern. This is because the LPS array construction takes $O(M)$ time, and the search phase takes $O(N)$ time.
        *   **Space Complexity**: $O(M)$ for storing the LPS array.

6.  **When a mismatch occurs in KMP, why does the text pointer (`i`) not backtrack?**
    *   **Answer**: The text pointer `i` does not backtrack because the LPS array provides sufficient information to know exactly how much of the previously matched text segment can serve as a prefix for a new potential match. By shifting the pattern pointer `j` to `lps[j-1]`, we are effectively aligning the longest proper prefix of the pattern (which is also a suffix of the partially matched pattern) with the corresponding part of the text. This ensures that no potential matches are missed, and every character in the text is visited at most a constant number of times.

7.  **Can KMP find overlapping occurrences of a pattern? How?**
    *   **Answer**: Yes, KMP can find overlapping occurrences. After a full match is found (when `j` reaches `M`), instead of resetting `j` to 0, we set `j = lps[j-1]`. This effectively shifts the pattern to align the longest proper prefix of the *matched* pattern that is also its suffix. The search then continues from this new `j` position in the pattern, allowing it to detect subsequent overlapping matches.

8.  **What are some real-world applications of the KMP algorithm?**
    *   **Answer**: KMP is used in:
        *   **Text editors/IDEs**: For efficient "Find" and "Find and Replace" operations.
        *   **Bioinformatics**: For searching specific gene sequences or motifs in large DNA/protein databases.
        *   **Network Intrusion Detection Systems (NIDS)**: To scan network traffic for known malicious patterns or signatures.
        *   **Plagiarism detection software**: To identify copied text segments.
        *   **Data compression**: As a component in algorithms that identify repeating patterns.

9.  **What are the main advantages and disadvantages of KMP?**
    *   **Answer**:
        *   **Advantages**: Optimal linear time complexity ($O(N+M)$), no backtracking in text, efficient for repetitive patterns, guaranteed worst-case performance.
        *   **Disadvantages**: More complex to understand and implement than naive algorithms, requires $O(M)$ extra space for the LPS array, might not always be the fastest in practice for random text compared to algorithms like Boyer-Moore (though KMP has better worst-case).

10. **Compare KMP with the Boyer-Moore algorithm.**
    *   **Answer**: Both KMP and Boyer-Moore are efficient string-searching algorithms.
        *   **KMP**: Pre-processes the *pattern* to create an LPS array, shifts the pattern based on partial matches, and never backtracks the text pointer. Its worst-case time complexity is $O(N+M)$.
        *   **Boyer-Moore**: Pre-processes the *pattern* to create two heuristic tables: the "bad character rule" and the "good suffix rule". It compares the pattern from right-to-left. Its average-case time complexity can be sub-linear ($O(N/M)$), making it very fast in practice for many inputs. However, its worst-case time complexity is $O(N \times M)$ (though rarely encountered with good implementations).
        *   **Key Difference**: KMP shifts based on *prefixes* of the pattern that are also *suffixes* of the matched part. Boyer-Moore shifts based on mismatches from the *right* end of the pattern, often allowing larger jumps. KMP is simpler to analyze for worst-case, while Boyer-Moore is often faster in average-case.
